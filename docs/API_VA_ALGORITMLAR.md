# SmartFlow — API ва алгоритмлар

Бу ҳужжат лойиҳадаги **ҳамма API**ни (қайси файлда, ким чақира олади, нима қайтаради) ва **ишлатилган алгоритмлар**ни (қаерда, қандай, нега) тушунтиради. API жадваллари кодни автоматик таҳлил қилиб (Python AST) тузилган — ҳамма 143 та эндпоинт киритилган.

## Тизим тузилиши

```
 Ота-она / ўқувчи иловаси ──►  ПУБЛИК СЕРВЕР  (64.188.67.36:8200, public_server/)
 Директор / ўқитувчи      ──►    │  /relay/... ──(тескари WebSocket туннел)──►  МАКТАБ СЕРВЕРИ (backend/)
 (web: /web/, Android APK)       │                                               ├─ PostgreSQL (асосий маълумот)
                                 ◄── /sync/events (ўзгаришлар навбати) ──────────┤
                                                                                 └─ камералар (RTSP) → юзни таниш
```

* **Мактаб сервери** (`backend/`, FastAPI + PostgreSQL, Docker): ҳамма асосий маълумот, камералар ва юзни таниш шу ерда. Мактаб тармоғида туради, интернетга порт очмайди.
* **Публик сервер** (`public_server/`, FastAPI): интернетдаги кириш нуқтаси. Web иловани (`/web/`) ва APK'ни беради, ота-она/ўқувчи учун ўз базаси бор, директор/ўқитувчи сўровларини туннел орқали мактаб серверига узатади.
* **Клиентлар:** `smartflow-web/` (React + TypeScript) ва `smartflow-android/` (Kotlin + Jetpack Compose).

**Кириш (ҳимоя):** ҳар сўровда `Authorization: Bearer <JWT>`. Токен ичида рол ва мактаб бор; эндпоинт ҳар доим маълумотни фойдаланувчининг ўз мактаби билан чеклайди. Жадвалдаги "Ким чақиради" устуни шу ролни кўрсатади.

## Мактаб сервери (`backend/`)

Интернетдан `http://64.188.67.36:8200/relay/<йўл>` орқали етиб борилади (релей туннели). Мактаб ичидан тўғридан-тўғри `http://<сервер>:8080/<йўл>`.

# Алгоритмлар: қаерда, қандай ва нега

## 1. Юзни таниш (давомат камералари)
**Файллар:** `backend/app/ai/live_detection.py`, `backend/app/ai/face_engine.py`

**Қандай ишлайди:**
1. Камера кадри (RTSP оқими) 2 баробар кичрайтирилади ва **InsightFace `buffalo_l`** моделига берилади. Унинг ичида иккита нейрон тармоқ бор: **RetinaFace** — кадрдаги юзларни топади, **ArcFace** — ҳар юзни **512 та сондан иборат вектор**га (embedding) айлантиради.
2. Ўқувчи қўшилганда унинг расмидан ҳам шундай вектор олиниб, шифрланган ҳолда базага ёзилади.
3. Камерадаги юз вектори синфдаги ҳар ўқувчи вектори билан **косинус ўхшашлик** бўйича солиштирилади: `cos = (a·b) / (|a|·|b|)`. Энг юқори натижа олинади (`argmax`).
4. Икки шарт бажарилсагина ўқувчи белгиланади:
   * ўхшашлик **≥ 0.40** (`SIMILARITY_THRESHOLD`);
   * энг яхши натижа иккинчи энг яхшидан камида **0.08** баланд (`MIN_MATCH_MARGIN`).

**Нега шундай:**
* **ArcFace** векторлари юз эгалари бўйича яхши ажралади: бир одамнинг турли расмлари бир-бирига яқин, бошқа одамларники узоқ. Шунинг учун ҳар ўқувчига модел қайта ўргатиш шарт эмас — битта расм етади.
* **Косинус ўхшашлик** векторнинг узунлигига эмас, йўналишига қарайди; ёруғлик ва масофа ўзгарганда ҳам барқарор. ArcFace айнан шу ўлчов билан ўргатилган.
* **Остона (0.40)** нотаниш одамни ўқувчи деб белгилашнинг олдини олади.
* **Фарқ шарти (0.08)** — икки ўхшаш ўқувчи (масалан, ака-укалар) бўлса ва модел иккиланса, тизим тахмин қилмайди, балки кейинги кадрни кутади. Нотўғри "келди"дан кўра кечроқ тўғри белги яхши.
* Қидирув синф ичида (ўнлаб ўқувчи) бўлгани учун оддий бирма-бир солиштириш етарли тез; махсус индекс (FAISS ва ҳ.к.) керак эмас.

## 2. Дарс давомида камера иш тартиби (жадвал)
**Файл:** `backend/app/ai/live_detection.py`

* **Рўйхат (roll call):** дарс бошланганда **10 дақиқа** давомида ҳар **10 сонияда** сканер — ким келганини аниқлайди.
* **Текширув:** кейин камера узилади ва ҳар **20 дақиқада** бир марта **10 сония** сканер қилади (синф бўйича ўзгартирса бўлади: `detect_duration_seconds`, `wait_duration_minutes`).
* Ўқувчи кетма-кет **2 цикл** (`ABSENT_AFTER_CYCLES`) кўринмаса — "келмади".
* **Гуруҳ режимида** камера синфни "позиция" жадвалидан олади: кун + вақт оралиғи + гуруҳ.

**Нега:** юзни таниш — оғир ҳисоб (CPU/GPU). Узлуксиз сканер сервер ресурсини еб қўяди ва бир неча камерада ишлолмай қолади. Дарс бошида зич, кейин сийрак текшириш — аниқлик ва ресурс ўртасидаги мувозанат. 2 цикл қоидаси эса битта ўтказиб юборилган кадр учун ўқувчини нотўғри "келмади" қилмасликка хизмат қилади.

## 3. Камераларни вақт бўйича сурилтириш (stagger)
**Файл:** `backend/app/ai/live_detection.py` (`stagger_offset`)

Ҳар камеранинг сканер вақти унинг `id`сига қараб бир неча сонияга сурилади.

**Нега:** ҳамма камера бир сонияда сканер бошласа, сервер бир зумда ортиқча юкланади. Сурилиш юкни вақт бўйича текис тарқатади.

## 4. Қотиб қолган кадрни аниқлаш
**Файл:** `backend/app/ai/live_detection.py`

Кадрнинг ҳар 16-пикселидан **MD5 хеш** олинади. Кетма-кет **90 марта** бир хил хеш келса — оқим қотиб қолган деб ҳисобланади ва камера қайта уланади.

**Нега:** баъзи RTSP камералар узилганда хато бермайди, балки охирги кадрни қайта-қайта юбораверади. Бутун кадрни солиштириш қиммат; сийрак пикселлар хеши арзон ва бу ҳолатни ишончли аниқлайди.

## 5. Камера жараёнини назорат (watchdog) ва уланиш вақт чеклови
**Файл:** `backend/app/ai/live_detection.py` (`_camera_watcher`, `_cam_heartbeat`, `_cam_generation`)

* Камера оқими ҳар циклда "тирик" сигнал (heartbeat) ёзади. Назоратчи ҳар 10 сонияда текширади: **120 сония** сигнал бўлмаса — оқим осилган, янгиси ишга туширилади.
* **Авлод рақами (generation):** эски осилган оқим кейин уйғонса, рақами эскириб қолгани учун ўзи чиқиб кетади — битта камерани иккита оқим бошқармайди.
* RTSP уланиш алоҳида оқимда **35 сония** чеклов билан очилади ва кутиб қолмайди.

**Нега:** OpenCV/FFmpeg баъзан тармоқ узилганда абадий "қотади". Шу сабабли камера соатлаб ишламай қолган эди. Хатони йўқотиб бўлмайди, лекин уни аниқлаб, автоматик тиклаш мумкин.

## 6. Келди / кечикди / мактабни тарк этди
**Файл:** `backend/app/services/attendance_service.py`

* Дарсга: бошланишдан **10 дақиқа** ичида кўринса — "келди", кейин — "кечикди".
* Кунлик давоматда: белгиланган вақт + **15 дақиқа**.
* Келган ўқувчи **30 дақиқа** кўринмаса — "мактабни тарк этди" (`LEFT_SCHOOL_AFTER_MINUTES`). **Гуруҳ режимида бу ишламайди** — ўқув марказида машғулот қисқа, тугагач кетиш табиий.
* Биринчи кўрилган вақт (`time_in`) бир марта ёзилади, `last_seen` ҳар кўрилганда янгиланади.

**Нега:** оддий вақт оралиғи қоидалари тушунарли ва директор текшира олади; "чегара" (grace) ўқувчини бир дақиқа кечикканига жазоламаслик учун.

## 7. Рейтинг ва аналитика
**Файл:** `backend/app/services/analytics_service.py`

* **Мактаб:** ҳар ўқувчининг чоракдаги баҳолари ўртачаси (SQL `AVG`), камайиш тартибида сараланади; баҳоси йўқлар охирида.
* **Гуруҳ режими (ўқув маркази):** баҳо йўқ, шунинг учун балл = **давомат фоизи** = (келди + кечикди) / жами кунлар × 100.
* **"Эътибор керак":** энг паст натижалилар ва ўтган чоракка нисбатан энг кўп тушганлар (айирма бўйича саралаш).
* **Кунлик график:** `GET /attendance/daily-trend` базада кун ва ҳолат бўйича гуруҳлаб санайди (`GROUP BY`) — минглаб сатрни телефонга юбормасдан.

**Нега:** ўртача ва фоиз — раҳбарият учун энг тушунарли кўрсаткичлар. Гуруҳлаш (агрегация) базанинг ўзида қилинади, чунки 1000+ ўқувчили мактабда хом сатрларни клиентга юбориш секин ва қиммат.

## 8. Дарс жадвалини автоматик тузиш
**Файл:** `backend/app/services/timetable_service.py`

**Очкўз (greedy) алгоритм + айланма (round-robin) танлов:**
1. Ҳар синф учун фанлар рўйхати — ўқитувчи бириктиришларидан.
2. Кунлар ва соатлар бўйича юрилади; ҳар бўш соатга навбатдаги фан қўйилади (айланма тартибда).
3. Агар шу фан ўқитувчиси шу пайт бошқа синфда банд бўлса — кейинги фан синаб кўрилади.
4. Аввал ёзувлари (давомат/баҳо) бор дарслар ўчирилмайди, фақат бўш жойлар тўлдирилади.

**Нега:** тўлиқ оптималлаштириш (масалан, чеклов масаласи ечувчиси) мураккаб ва секин. Мактаб учун "ўқитувчи бир вақтда икки жойда бўлмасин, фанлар текис тарқалсин" талабини очкўз усул тез ва етарли бажаради; директор кейин қўлда тузатади.

## 9. Камера позицияларида вақт тўқнашуви
**Файл:** `backend/app/services/camera_position_service.py`

* **Фаол позиция:** ҳозирги кун ва вақтни қамраб олган позиция; бир нечта бўлса — аниқ кунга ёзилгани ва эртароқ бошлангани устун.
* **Тўқнашув:** икки оралиқ кесишади, агар `бошланиш1 < тугаш2` ва `бошланиш2 < тугаш1` (кунлари ҳам мос келса).

**Нега:** бу оралиқлар кесишишининг стандарт ва энг содда текшируви. Битта камера бир вақтда икки гуруҳни кузатмаслиги шарт.

## 10. Қоғоз журнални суратдан ўқиш
**Файл:** `backend/app/services/journal_scan_service.py`, `backend/app/services/gemini_client.py`

1. Расм **Gemini** (Google) кўриш моделига юборилади ва жавоб **қатъий JSON схема**да (исм, сана, баҳо) сўралади.
2. Журналдаги исм синф рўйхатидаги исмлар билан **`difflib.SequenceMatcher`** орқали солиштирилади (0..1 ўхшашлик).
3. Энг яхши ва иккинчи натижа фарқи **0.08** дан кам бўлса — ишонч 0.5 гача туширилади ва ўқитувчидан тасдиқ сўралади.

**Нега:** қўлёзма ва имло хатолари туфайли исм ҳеч қачон аниқ мос келмайди ("Каримов" — "Карймов"). `SequenceMatcher` бу ҳолатда енгил ва ишончли; фарқ шарти эса иккита ўхшаш исмда нотўғри ўқувчига баҳо ёзилмаслиги учун (юзни танишдаги мантиқ билан бир хил). Охирги қарорни ўқитувчи қилади.

## 11. ИИ билан тест тузиш
**Файл:** `backend/app/services/material_ai_service.py`, `backend/app/services/gemini_client.py`

* Gemini'дан саволлар **JSON схема** бўйича сўралади (вариантлар ва тўғри жавоб мажбурий).
* Жавоб текширилади (`_validate`): бузуқ ёки чала саволлар ташланади. Савол етмаса — **3 мартагача** қайта сўралади, етишмаган сон билан.
* Савол турлари текис тақсимланади: `divmod(сон, турлар)` — қолдиқ биринчи турларга биттадан.
* Gemini хизмати жавоб бермаса — бир неча моделга навбат билан ўтилади, ҳар бирида **2 ва 5 сония** кутиб қайта уринилади.

**Нега:** тил модели баъзан нотўғри формат ёки кам савол қайтаради. Схема + текширув + қайта уриниш натижани ишончли қилади; захира моделлар эса битта модел тўлиб қолганда ҳам хизмат ишлашини таъминлайди.

## 12. Мактаб ↔ публик сервер синхронлаши (outbox)
**Файллар:** `backend/app/services/sync_outbox_service.py`, `backend/app/background/sync_worker.py`, `public_server/app/routers/sync_router.py`

* **Transactional outbox** намунаси: баҳо, давомат ва ҳ.к. ўзгарганда, ўша базавий транзаксия ичида "юборилиши керак" навбатига ёзув қўшилади.
* Фон ишчиси навбатдан **50 тадан** олиб, публик серверга юборади.
* Хато бўлса — **экспоненциал кутиш**: `min(2^уриниш × 5, 300)` сония (5, 10, 20, 40 ... 300).

**Нега:** интернет узилиши мумкин. Навбат маълумотни йўқотмайди ва интернет қайтгач ҳаммаси етиб боради. Экспоненциал кутиш эса сервер ишламаган пайтда уни тинмай сўров билан бостирмаслик учун.

## 13. Тескари туннел (релей)
**Файллар:** `public_server/app/routers/relay_router.py`, мактаб тарафида туннел мижози

* Мактаб сервери публик серверга **ўзи чиқиб** доимий WebSocket билан уланади (интернетда порт очиш шарт эмас).
* Ташқаридан `/relay/...` сўрови келса, публик сервер унга **UUID** беради, туннел орқали юборади ва `asyncio.Future` орқали жавобни кутади (**400 сония** чеклов). Мактаб уланмаган бўлса `503 school_offline`.
* Камера видеоси ва бошқа WebSocket'лар ҳам шу туннелда ўз навбати (`asyncio.Queue`) билан узатилади.

**Нега:** мактаб интернетида кўпинча оқ IP ва порт очиш имконияти йўқ. Тескари уланиш ҳар қандай тармоқда ишлайди; UUID+Future эса битта туннел орқали бир вақтда кўп сўровни аралаштирмасдан узатади.

## 14. Илованинг серверни топиши (Android)
**Файл:** `smartflow-android/.../core/network/SchoolServer.kt`

1. Аввал сақланган мактаб манзили (тез).
2. Бўлмаса — мактаб тармоғида **UDP broadcast** (255.255.255.255) — сервер ўз портини жавоб беради.
3. Топилмаса — интернет орқали **релей** (`/relay/`).

**Нега:** мактаб ичида тўғридан-тўғри уланиш тез (видео ҳам равон), ташқарида эса релей. Фойдаланувчи ҳеч нарса созламайди.

## 15. Хавфсизлик
**Файллар:** `backend/app/utils/security.py`, `backend/app/utils/face_crypto.py`, `public_server/app/services/verification_service.py`

* **Директор/ўқитувчи пароли:** `bcrypt` (секин, тузли хеш — ўғирланган базадан паролни тиклаш қийин).
* **Токен:** JWT, **HS256** имзо; ичида рол ва мактаб.
* **Юз векторлари:** **Fernet** (AES-128-CBC + HMAC-SHA256) билан шифрланади; калит фақат мактаб серверида. Публик серверга юз маълумоти чиқмайди.
* **SMS код (ота-она):** 6 хонали, `secrets.randbelow` (криптографик тасодифий), **5 дақиқа** амал қилади, **5** уринишдан кейин ёпилади; базада тузли SHA-256 хеш; текширув `hmac.compare_digest` (вақт ҳужумига қарши).

**Нега:** юз маълумоти — шахсий биометрия, шунинг учун шифрланган ва мактабдан чиқмайди. Тасодифий код ва уринишлар чеклови кодни танлаб топишнинг олдини олади.

> **Тавсия:** ота-она ва ўқувчи пароллари публик серверда тузли SHA-256 билан сақланади. Бу bcrypt'дан кучсизроқ (SHA-256 жуда тез ҳисобланади). Келгусида уларни ҳам bcrypt'га ўтказиш маъқул.
